# ZK circuit

The arm that keeps liabilities private. A Noir circuit rebuilds the customer tree,
sums the balances per asset and proves each total stays under a public floor; the
UltraHonk verifier checks that proof on-chain. Nothing about any balance, and not even
the totals, leaves the prover: the epoch publishes a root, the epoch context and one
floor per asset.

## Layout

| Path | What it is |
| --- | --- |
| `circuit/src/main.nr` | The circuit: 8 leaves, per-asset sums, floors as public inputs, the root as output |
| `contracts/MultiAssetSolvencyRegistry.sol` | Per-asset reserve check, proof verification, Chainlink-style valuation, epoch record |
| `contracts/MultiAssetHonkVerifier.sol` | Generated by `bb write_solidity_verifier`; regenerate only when the circuit changes |
| `prover/multiAssetTree.ts` | The tree, the epoch context and `verifyBundle`; byte-matches the circuit |
| `prover/buildMultiAssetTree.ts` | Writes `circuit/Prover.toml` from `shared/customers.csv` and `snapshot.json` |
| `prover/fetchSnapshot.ts` | Reads context, reserves, prices and rounds off a deployed registry |
| `bench/` | Gate counts, proving time and memory from N = 8 to the ceiling |
| `script/demo.ts` | Anvil walkthrough (`make zk-demo`) |

Roles, reserve control, sampling and the publication window come from
`shared/contracts/ReserveRegistry.sol`.

## Encoding

    leaf    = Poseidon2(username, salt, assetId, amount)
    parent  = Poseidon2(left, right)
    root    = Poseidon2(treeRoot, context)
    context = keccak256(abi.encode(chainId, registry, epochId)) mod p

    publicInputs = [floor0, floor1, floor2, context, rootHash]

The context binds a proof to one registry, one chain and one epoch id, so a proof
cannot be replayed into the next epoch or onto another deployment. Amounts are `u64`
in the asset's base units; Noir rejects an overflowing per-asset sum, so a wrapped
total cannot satisfy the circuit.

## The on-chain check

`submitEpoch` compares the attested reserve of each asset with that asset's floor
before it verifies the proof, so a surplus in one asset never covers a shortfall in
another. Prices are read from a pinned Chainlink round only to publish a USD figure;
they play no part in the solvency decision.

## Build and prove

    make zk-snapshot REGISTRY=0x...   # refresh snapshot.json from a deployed registry
    make zk-fixtures                  # customers.csv + snapshot.json -> Prover.toml
    make zk-check                     # nargo execute
    make zk-prove                     # write_vk, prove, verify, then refresh fixtures
    make zk-verifier                  # regenerate the Solidity verifier
    make zk-circuit-test              # the circuit's own tests
    make zk-bench                     # gate counts and proving cost by size

`zk-verifier` changes the verification key, which invalidates the committed proof, the
deployed verifier and every benchmark figure. Run it only when the circuit changes.

## Demo

    anvil --silent &
    forge build
    make zk-demo

Deploys the verifier, registry and mock feeds, runs the reserve flow, submits a real
proof, and shows the same proof being refused in the next epoch.

## Customer check

`verifyBundle` takes the customer's own username, salt and expected amounts, and the
root read from the chain. A part whose username or salt is not the customer's own is
rejected, so a leaf built for one customer cannot be served to another; path encodings
must have the circuit's depth, so a leaf cannot be counted twice.

## Limits

Floors are public: set to the reserves they reveal nothing that is not already on-chain,
set to the liabilities they publish the totals. The committed circuit holds 8 leaves.
Its shape compiles up to 8,192; the flat-array form in `bench/generate.ts` reaches 16,384
(`bench/results.md`). Leaves are (customer, asset) pairs, not customers. Inclusion
proves one customer is present, never that everyone is.
